手机装哪个 APK

默认同时编译 arm64-v8a 与 x86_64，产出 universal APK，手机和模拟器都能装。发给用户优先用 universal（或 arm64）包：绝大多数真机（含 vivo / iQOO）只认 arm64-v8a，只含 x86_64 的包会提示「指令集与当前设备 ABI 均不匹配」。模拟器可用 x86_64 包，体积更小。

测试签名只能自己装，不能上架

测试 keystore 由 signing/android/gen-test-keystore 生成，文件名带 TEST-SIGNING-ONLY，适合真机调试与内测；Google Play 会拒绝测试签名包。正式上架请切到「正式签名」，用你自己的上传密钥并开启 Play App Signing。

仅本地测试：生成的证书是自签的

自签证书不会被系统信任。安装应用或打开页面时，系统与 WebView 会弹出证书警告；它不能用于真实用户，也不要在生产环境分发。正式发布请在构建机导入可信证书并完成签名。

导入证书不进导出包

证书和私钥留在构建机，产物只带配置引用；私钥一旦打进压缩包，导出校验会直接失败。

http 协议不会使用证书

选 http 时 HTTPS 模式会被重置为 none，导出包不会生成或写入证书。需要 TLS 请把协议改成 https，再按需生成测试证书或在构建机导入可信证书。

运行环境

选择随包的后端模板；Web 静态产物本身不依赖后端，选「无后端」也仍然可单独部署。

数据库与 Redis

留空 / 选「不使用」即不启用。这里只保存连接参数，向导不会连接、建库或改写任何数据库；密码不会写进导出包。

Redis 缓存

默认关闭。示例端口刻意避开常用的 6379，避免误连本机已有实例。

密码的存放与使用

密码只保存在本机站点配置里，界面不会回显已保存的明文；不修改输入框就保留原值。导出包里的 config.yaml 只写空密码，部署时通过 LC_DB_PASSWORD / LC_REDIS_PASSWORD 注入。

站点域名与访问路径

生成的 nginx 用该域名做 server_name，证书 SAN 与 CORS 允许来源跟着走。留空则回退 localhost，并在导出结果里提示「仅本机可用」。

# 08 中间件与配置中心：连接、开关与配置分层

> 本篇目标：会在中间件页面开启数据库 / 缓存 / 对象存储等连接并填参数；会建自定义中间件；会在配置中心按环境管理键值，并看懂「当前生效值来自哪一层」。
>
> 这两个页面都**按站点**生效。进入后先确认顶栏「站点」下拉，未选站点时所有编辑是禁用的。

---

## 一、两个页面分别管什么

| | 中间件 `middleware.html` | 配置中心 `config-center.html` |
| --- | --- | --- |
| 管什么 | 数据库、缓存、对象存储、消息队列、搜索、反向代理、自定义连接 | 业务配置键值，如站点名、API 前缀、部署地址 |
| 表单形态 | 按预置分组开关 + 字段 | 按分组的键值表 |
| 保存到哪 | 站点中间件配置 | 站点配置中心定义与 dev/prod 层值 |
| 典型用途 | 让后端能连 PostgreSQL / Redis | 配 `APP_MODE`、`API_BASE_URL`、`PUBLIC_BASE_URL` |

两个页面顶栏可以互相跳转，都有「导出 JSON」。

---

## 二、中间件页面导览

进入后左侧：

- 「内置」：9 个预置连接分组；
- 「自定义」：你自己定义的连接键值，底部有「新增自定义中间件」；
- 「整份配置」：导入 / 导出 JSON。

主区域顶部有「保存」按钮和保存状态。未选站点时主区域显示「先选择一个站点」，所有编辑禁用。

底部状态栏提示：

> 密钥保存在站点 .lowcode 目录，不写入项目 JSON

### 保存后发生什么

页面上的说明写得很明确：

- 内置项同步到导出后端的 `database` / `cache` / `middlewareGroups`；
- 自定义项落到 `customMiddleware`；
- 密钥单独存放，不写进项目 JSON；
- 内置键名是 `LC_CFG_<GROUP>_<FIELD>`；
- 自定义键名是 `MW_<ID>_<FIELD>`，后端用 `configCenter.get()` 读取。

## 三、内置中间件

### 9 个分组

| 分组 | 类别 | 作用 | 是否由平台直接连接 |
| --- | --- | --- | --- |
| SQLite | 数据库 | 单文件数据库，适合本机与小型部署 | 是 |
| PostgreSQL | 数据库 | 通过 pg 驱动连接 | 是 |
| MySQL | 数据库 | 通过 mysql2 驱动连接 | 是 |
| MariaDB | 数据库 | 协议兼容 MySQL，导出复用 mysql 组 | 是 |
| Redis | 缓存 | 缓存与轻量消息队列共用 | 是 |
| 对象存储 | 注入 | S3 / OSS / COS 连接信息 | 否，只注入配置 |
| 消息队列 | 注入 | Redis / Kafka / RabbitMQ 连接信息 | 否，只注入配置 |
| 搜索 | 注入 | OpenSearch / Elasticsearch 连接信息 | 否，只注入配置 |
| 反向代理 | 注入 | 上游地址与请求体限制 | 否，只注入配置 |

「注入」的意思是：平台只把配置键值写进导出后端，真正的连接代码要你在用户区自己写。

### 开启一个分组

1. 在卡片右上角把开关打开；
2. 卡片展开配置字段；
3. 按字段填写；
4. 点顶部「保存」。

### 数据库只能启用一个

SQLite、PostgreSQL、MySQL、MariaDB 同属数据库。开启其中一个时，如果已有另一个启用，会弹确认：

> 数据库中间件只能启用一个
> 当前已启用 XXX，是否关闭它并启用 YYY？

确认后：

- 旧数据库分组被关闭；
- **旧分组的配置与密钥会被清空**；
- 新分组按默认值初始化。

这是有意的互斥设计，不是 bug。

### 关闭会清空

关闭任意分组都会先确认：

> 关闭后会清空这一组已填写的配置和密钥，导出产物里也不会再出现对应键。

确认按钮是「关闭并清空」。关掉再打开，原来填的内容不会回来。所以要临时停用又不想丢配置，先「导出 JSON」备份。

### 常用字段速查

**SQLite**

| 字段 | 默认 |
| --- | --- |
| 数据库文件 | `data/app.db` |

**PostgreSQL / MySQL / MariaDB**

| 字段 | 默认 |
| --- | --- |
| 主机 | `127.0.0.1` |
| 端口 | PostgreSQL `15432`；MySQL / MariaDB `13306` |
| 库名 | `app` |
| 账号 | `lc` |
| 口令 | 空（敏感） |
| SSL 模式 | 仅 PostgreSQL，默认 `disable` |
| 最大连接 | `10` |
| 连接超时 | `5` 秒 |

默认端口刻意避开本机常见的 5432 / 3306，减少误连已有服务。

**Redis**

| 字段 | 默认 |
| --- | --- |
| 连接地址 | `redis://127.0.0.1:16379/0` |
| 默认 TTL | `30` 秒 |
| 键前缀 | `lc:` |
| 口令 | 空（敏感） |

**对象存储**

驱动 `s3`、Endpoint、Bucket、Region、Access Key（敏感）、Secret Key（敏感）。

**消息队列**

驱动、连接地址、队列 / Topic。

**搜索**

驱动、连接地址、索引。

**反向代理**

上游地址（必填，默认 `http://127.0.0.1:8080`）、请求体上限（默认 `1m`）。

### 敏感字段

带「敏感」标记的字段：

- 默认以密码框显示；
- 点「查看」才临时显示明文，再点「隐藏」恢复；
- 导出时可选择把敏感值打码；
- 不写进项目 JSON。

## 四、自定义中间件

用于平台没有预置、但你想统一注入的连接信息。

### 新增

点左侧「新增自定义中间件」，或主区域「自定义中间件」标题旁的「新增」。弹窗字段：

| 字段 | 规则 |
| --- | --- |
| 名称 | 必填，最多 64 字 |
| ID | 小写字母开头，可含数字、下划线、短横线，≤ 32 字符 |
| 说明 | 可留空 |
| 配置字段 | 至少一个 |

每个配置字段一行：

- `键`：字母开头，可含数字和下划线；
- `显示名`；
- `类型`：文本 / 数字 / 布尔 / 枚举；
- `敏感`：勾选后掩码显示；
- `值`；
- `删除`。

枚举字段必须填「可选值」，逗号分隔。

键不能重复，也不能为空。空键会被忽略。

### 键名规则

导出到配置中心的键名是：

```text
MW_<ID>_<字段>
```

例如 ID 是 `kafka`、字段是 `broker`，得到：

```text
MW_KAFKA_BROKER
```

### 删除

删除前会确认：

> 删除后，这份中间件在导出产物里的 MW_* 键也会消失。

## 五、中间件的导入导出

### 导出

点左侧「整份配置」→「导出 JSON」，弹窗可选：

```text
[ ] 导出时把敏感值打码（导入时保留原有密钥）
```

- 不勾选：导出包含敏感值明文。弹窗会警告「这个文件等同于密钥清单」；
- 勾选：敏感值写成 `***`，适合分享结构；
- 文件格式标识是 `lowcode-middleware` v1。

### 导入

点「导入 JSON」选择文件。读取后会先列出冲突：

- 内置组：当前已启用且配置不同；
- 自定义：同 ID 已存在；
- 未知内置组会被忽略并提示。

然后选导入方式：

| 方式 | 行为 |
| --- | --- |
| 合并 | 只覆盖导入文件里启用的组；未出现的组保持当前状态 |
| 覆盖 | 整份替换当前中间件配置；未启用的组会被清空 |

点「应用到界面」后才改界面，**还要再点顶部「保存」才写入站点**。这步很容易漏。

## 六、配置中心导览

进入 `config-center.html` 后左侧：

- 「环境」：`dev` / `prod` 两个按钮；
- 「分组」：站点、后端、部署、中间件；
- 「整份配置」：导入 / 导出。

主区域按分组渲染表格，列是：

```text
键 | 类型 | 当前生效值（dev 或 prod） | 来源 | 操作
```

顶部有保存按钮和状态。未选站点时同样禁用。

### 环境

- `dev` 和 `prod` 各自保存一套层值；
- 定义（键、类型、默认值、说明、是否敏感）是**两个环境共用**的；
- 切换环境只切换显示和编辑的层值，不会丢另一套；
- 保存时两个环境一起写入。

### 分组

| 分组 | 适合放什么 |
| --- | --- |
| 站点 | 站点名称、语言、版权 |
| 后端 | 运行模式、接口前缀、分页上限 |
| 部署 | 公开地址、部署渠道、健康检查路径 |
| 中间件 | 自定义中间件字段、用户补充的连接参数 |

### 推荐键

新建站点或某分组为空时，页面会给出推荐键，例如：

```text
SITE_NAME           文本
SITE_LOCALE         枚举（zh-CN / en-US）
SITE_COPYRIGHT      文本
APP_MODE            枚举（standard / strict）
FEATURE_NEW_UI      布尔
API_BASE_URL        文本（默认 /api）
DATA_MAX_PAGE_SIZE  数字（默认 100）
PUBLIC_BASE_URL     文本
DEPLOY_CHANNEL      枚举（systemd / docker / static）
HEALTH_PATH         文本（默认 /api/health）
MIDDLEWARE_HEALTH_INTERVAL_SECONDS  数字（默认 30）
```

点推荐项即可加入，不需要手敲键名。

## 七、添加和编辑配置项

### 添加

点分组标题右侧「添加配置项」，弹窗：

| 字段 | 规则 |
| --- | --- |
| 配置键 | 大写字母、数字、下划线，`[A-Z][A-Z0-9_]*`，≤ 64 字符；创建后不可改 |
| 分组 | 站点 / 后端 / 部署 / 中间件 |
| 类型 | 文本 / 数字 / 布尔 / 枚举 |
| 敏感值 | 勾选后按密钥处理 |
| 默认值 | 可留空 |
| 枚举可选值 | 类型为枚举时必填，逗号分隔 |
| 说明 | 可留空，≤ 512 字 |

配置键不能占用保留前缀：

- 不能以 `LC_` 开头；
- 不能以 `MW_` 开头；
- 不能与内置中间件的环境变量名冲突。

否则会提示「配置键与内置中间件环境变量或 MW_ 前缀冲突」。

### 编辑

点行内「编辑」：

- 配置键只读；
- 可改类型、敏感标记、默认值、枚举值、说明；
- 下方编辑当前环境（dev 或 prod）的各层值。

### 各层

点行内「各层」可以看到同一个键在每一层的取值：

```text
内置默认
平台生成
站点覆盖
环境变量
启动参数
```

### 删除

点「删除」会确认：

> 会同时清理 dev / prod 两个环境里这一键的所有层值。

删除不可撤销，确认前先导出备份。

### 由自定义中间件生成的键

配置中心「中间件」分组里，会出现一些**只读行**，操作列显示「由自定义中间件生成」。它们来自中间件页面的自定义字段，不能在配置中心编辑或删除，要去中间件页面改。

## 八、配置分层：五层怎么覆盖

配置中心按固定顺序解析，后面的层覆盖前面的层：

```text
1. 内置默认      定义的 default
2. 平台生成      config.generated.yaml
3. 站点覆盖      config.yaml
4. 环境变量      LC_CFG_<KEY>
5. 启动参数      --cfg KEY=VALUE
```

表格里的「来源」列显示最后命中的那一层。层级含义：

| 层 | 谁来设置 | 适合做什么 |
| --- | --- | --- |
| 内置默认 | 定义里的默认值 | 开箱可用的兜底 |
| 平台生成 | 导出时由平台写入 | 平台根据站点生成的默认配置 |
| 站点覆盖 | 你在配置中心填的层值 | 这个站点的固定配置 |
| 环境变量 | 部署机器的环境变量 | 不同机器不同值，例如生产数据库地址 |
| 启动参数 | 启动命令的 `--cfg` | 临时覆盖、排障 |

### 写法

环境变量：

```text
LC_CFG_APP_MODE=strict
LC_CFG_API_BASE_URL=/api/v2
```

启动参数：

```bash
./server --cfg APP_MODE=strict --cfg API_BASE_URL=/api/v2
```

### 敏感值的特殊规则

敏感配置只允许放在**环境变量**或**启动参数**层：

- 内置默认、平台生成、站点覆盖三层对敏感键不可用；
- 编辑弹窗里这三层会显示「密钥不允许写这一层」并禁用；
- 配置中心的生效值默认显示 `••••••`，点「查看」才显示；
- 导出时可选打码。

### 一个覆盖例子

```text
定义默认 APP_MODE = standard
站点覆盖 APP_MODE = strict
环境变量 LC_CFG_APP_MODE = standard
```

最后生效的是环境变量层的 `standard`，来源显示「环境变量」。

所以排障时先看「来源」，不要只看站点里填了什么。

## 九、保存、导入与导出

### 保存

点顶部「保存」后：

- 定义与 dev/prod 层值写入站点；
- 来源列重新计算；
- 保存状态变成「已保存」。

没点保存就关页面，改动不会写入站点。

### 导出

「整份配置」→「导出 JSON」，弹窗说明：

- 默认导出包含敏感值明文，文件等同于密钥清单；
- 勾选「导出时把敏感值打码（导入时保留原有密钥）」后，敏感值写成 `***`；
- 文件包含 `definitions` 和 `environments.dev` / `environments.prod`；
- 格式标识 `lowcode-config-center` v1。

### 导入

选择文件后会校验：

- `kind` 必须是 `lowcode-config-center`；
- `schemaVersion` 必须是 1；
- 必须有 `definitions` 数组；
- 键名合法、不重复、不占用保留前缀；
- 枚举必须有可选值；
- 敏感值不允许出现在 `values` / `site` 层。

然后列出定义冲突（类型 / 敏感标记 / 分组不同），让你选：

| 方式 | 行为 |
| --- | --- |
| 合并 | 导入文件里的键覆盖同名键，其他键保持 |
| 覆盖 | 整份替换当前定义与两个环境的层值 |

点「应用到界面」后只是改界面，**还要点顶部「保存」**。

打码的 `***` 在导入时会尽量保留原有密钥，不会把真密钥覆盖成三个星号。

## 十、纯静态项目能用吗

能打开、能编辑、能保存。但：

- 中间件与配置中心的内容，只有在导出时附带后端模板的情况下，才会写进服务端配置；
- 纯静态产物没有服务端，这些配置不会被执行；
- 导出时选「无后端」，中间件/配置不会变成可运行的连接。

所以纯静态项目里配这些，更多是为了以后转成带后端导出时保留配置，不要期待静态站会连数据库。

## 十一、常见问题

### 1. 为什么所有输入都是灰的？

没选站点。用顶栏「站点」下拉或在主区域的站点选择器选一个。

### 2. 关闭中间件后配置没了，能恢复吗？

不能。关闭即清空配置和密钥。要保留就先导出 JSON 备份，或先复制一份站点。

### 3. 想同时用 PostgreSQL 和 MySQL，可以吗？

不可以。数据库中间件只能启用一个。需要两个库时，用其中一个作为主库，另一个在用户代码里自己连，并通过自定义中间件注入连接信息。

### 4. 对象存储填了，为什么上传还是不通？

「对象存储」是注入型分组，平台只保存并注入配置，不替你写连接代码。上传逻辑要在用户区或后端组件里实现。

### 5. 配置中心改了值，为什么生效值没变？

按顺序查：

- 是否点了「保存」；
- 是否看错环境（dev / prod）；
- 「来源」列是否显示更高优先级的层（环境变量 / 启动参数）在覆盖；
- 键名是否与代码读取的键一致。

### 6. 为什么敏感键在站点覆盖层填不了？

敏感值只允许环境变量或启动参数层。这是防止密钥被写进项目 JSON 和导出包。

### 7. 导入后为什么没变化？

导入只改界面。必须再点顶部「保存」。

### 8. 自定义中间件的键在配置中心能改吗？

不能。它们显示为「由自定义中间件生成」，要去中间件页面改字段。

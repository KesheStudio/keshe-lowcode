# 12 常见问题与排错

> 本篇目标：出问题时知道先看哪里、按什么顺序排除，而不是乱点或直接改数据文件。
>
> 排错顺序固定为：**启动 → 首页/项目 → 画布/保存 → 数据/接口 → 导出/部署**。越往前的问题越基础，先确认前面的都没问题，再往后查。

---

## 一、先做三件事

任何故障，先按这三步走：

### 1. 看启动窗口最后 10 行

启动失败的原因和下一步动作通常已经打印出来。不要只看最后一行报错，往前多翻几行。

### 2. 打开启动诊断页

服务起来但页面异常时，访问：

```text
http://127.0.0.1:9780/diagnostics.html
```

它会检查：

- 服务是否在运行；
- 是否处于只读模式（磁盘不可写）；
- 实际服务地址、数据目录、模式、启动时间；
- 上次启动错误摘要；
- 给出“服务没启动”和“服务已运行但编辑器打不开”的分步指引。

端口被自动换过时，诊断页地址要用新端口。

### 3. 运行自检

```bash
npm run doctor
```

逐项看哪条没通过：

| 检查项 | 不通过时怎么办 |
| --- | --- |
| Node 版本 | 装 Node 20 LTS 或更高，重开终端 |
| platform.config.json | 按提示修改具体字段 |
| 依赖已安装 | `npm install` |
| 锁文件 | 安装后保留 `package-lock.json` |
| vendor/jszip.min.js | `npm run vendor:sync` |
| 无 CDN 引用 | 把外链脚本/样式/字体改成本地 vendor |
| 数据目录可写 | 检查权限、磁盘空间、只读挂载 |
| 产物无外链 | 清理导出产物里的外链引用 |
| 原子写自检 | 确认磁盘未满、安全软件没拦截 |
| 端口可用 | 关闭占用程序，或改 `platform.port` |
| 上次启动错误 | 按 `logs/boot-error.json` 修完再启动 |

自检退出码非 0 表示有项没过。

### 4. 看日志

```text
logs/start-port.json     本次请求端口、实际端口、pid
logs/boot-error.json     最近一次启动错误（message/stage/at）
```

导出包的日志在包内 `logs/`，见第 10 章。

## 二、启动类问题

### 1. 双击 `start.cmd` 闪一下就没了

常见原因：

- Node 没装或版本低于 20；
- 依赖安装失败；
- `platform.config.json` 校验不通过；
- 端口连续 20 个都被占用。

先右键「以管理员身份运行」看窗口（如果有），或打开 PowerShell 执行：

```powershell
npm start
```

让错误留在窗口里。再跑 `npm run doctor`。

### 2. 提示 Node 版本过低

装 Node 20 LTS 或更高，重开终端后执行 `node -v` 确认。不要只升级 npm。

### 3. 依赖安装失败

- 检查 npm 源：`npm config get registry`；
- 公司网络需要代理时先配代理；
- 手动执行 `npm install` 看完整输出；
- 删除 `node_modules` 后重装（先确认没有别的进程占用）。

### 4. 端口被占用

- 一键脚本会自动往后找 20 个端口，并打印「端口 X 被占用，改用 Y」；
- 以打印地址为准，不要继续用 9780；
- 要固定端口，关闭占用程序，或改 `platform.config.json` 的 `platform.port`。

查占用者：

```powershell
netstat -ano | findstr :9780
```

```bash
lsof -i :9780
```

### 5. 打不开页面，提示 `file://`

你双击了 HTML 文件，没有通过 http 访问。必须用：

```text
http://127.0.0.1:<实际端口>/
```

不要双击 `index.html`，也不要双击导出产物里的 `index.html`。

### 6. 服务已运行，但编辑器打不开

按诊断页的三条指引：

1. 端口是否和服务打印的一致；
2. 启动窗口是否有「只读模式」提示；
3. `npm run doctor` 哪项没过。

### 7. 进入只读模式

顶部会常驻提示。原因：

- 数据目录权限不足；
- 目录被只读挂载；
- 磁盘空间不足；
- 站点目录恢复失败。

只读模式下可以浏览，但保存、删除、导出都会被禁用。先修权限/磁盘，再重启服务。

### 8. 上次启动错误

看 `logs/boot-error.json` 的：

```json
{ "at": "...", "stage": "boot", "message": "..." }
```

按 `message` 修；修好后重启，启动成功会清除这个文件。

## 三、首页与项目

### 1. 项目卡片显示「待修复」或进不去

说明站点目录结构异常，平台把它标记为 `needs-repair`，只读浏览。

处理：

1. 先备份整个站点目录；
2. 去 `data/sites/<站点ID>/backups/` 找最近的自动备份；
3. 按 `manifest.json` 把受影响文件复制回去；
4. 仍不行就恢复整站备份（第 11 章）；
5. 不要直接手改 `site.json` / `project.json` 试。

### 2. 项目列表少了站点

- 检查 `data/sites/` 下目录是否还在；
- 检查 `site.json` 是否存在且能解析；
- 迁移后目录名是否和 `site.json.id` 一致；
- 服务是否运行在另一个数据目录（看诊断页）。

### 3. 新建项目后模板没生效

会提示「起步模板套用失败……已创建空白项目，可在模板库重试」。

按提示去模板库重新套用。项目本身还在。

### 4. 项目类型选错了

当前没有一键切换类型。要么新建带后端项目迁移内容，要么在导出向导里选后端模板（只对本次导出生效）。详见第 02 章。

## 四、Builder 画布与保存

### 1. 画布空白 / 提示「画布渲染失败」

按顺序：

1. 点画布工具栏「重新加载」；
2. 看浏览器控制台（F12 → Console）的第一条红色错误；
3. 检查当前页是否有刚写的实例级 HTML/JS 覆盖；
4. 把覆盖清空或点「恢复默认」，看是否恢复；
5. 检查页面限宽限高是否填了非法值；
6. 仍不行，换一个页面看是否单页问题。

画布渲染失败会同时写状态栏，错误标题通常带具体原因。

### 2. 插入区块没反应 / 跑到页末

插入规则是：

- 选中容器 → 放进容器；
- 其它情况 → 追加到当前页末尾。

想插到指定位置，先在图层树选中容器或目标位置。

### 3. 拖不动区块

- 自由定位模式下用指针拖动和右下角手柄缩放，不走普通拖拽排序；
- 按在输入框/可编辑区域上时，拖动被输入操作占用；
- 拖动中按 `Esc` 会取消。

### 4. 保存失败

看保存状态徽标和状态栏文案：

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 一直「保存中…」 | 服务无响应 / 网络断开 | 看服务窗口，刷新页面 |
| 「保存失败」+ 只读提示 | 数据目录不可写 | 修权限或磁盘 |
| 保存失败 + 409 冲突 | 另一个标签页/窗口也改了同一页 | 只保留一个编辑窗口，刷新后重做 |
| 保存失败 + 体积错误 | 单文件或站点超限 | 拆页面、压缩图片 |
| 页面尺寸不合法 | 限宽限高格式错 | 改成 `数字 + px/vh/vw/%/rem` |

保存失败时先别关页面：底部会显示「有未保存改动（草稿已留存）」，草稿可能还在本地。

### 5. 改了但刷新后没了

- 看是否点过保存 / 等自动保存完成；
- 看状态栏是否「已与磁盘同步」；
- 多标签页同时编辑会导致后保存覆盖先保存，只留一个窗口。

### 6. 撤销/重做不生效

- 点顶栏撤销/重做按钮，或 `Ctrl+Z` / `Ctrl+Shift+Z`；
- 撤销只覆盖当前编辑会话，不跨刷新；
- 如果刚做了保存，撤销后要再保存才会落盘。

### 7. 区块看不见了

- 属性面板「区块可见」是否被取消；
- 是否在自由定位下被拖出可视范围；
- 实例 HTML 覆盖是否把可见节点删掉了；
- 组件 JS 是否报错导致渲染中断。

### 8. 页面限高后不能滚动

限高会加 `overflow:auto`，应在页面内部滚动。如果没滚动，检查是否有实例 CSS 覆盖了 `overflow`。

## 五、组件、模板、主题

### 1. 内置组件改不了

内置组件只读。两种做法：

- 只想改某个实例：用该实例的「实例级代码覆盖」；
- 想改组件本身：点「复制为自定义」。

### 2. 自定义组件插入后是空的

正常。实例字段默认空，需要在属性面板填。组件库里的默认值只是预览样例。

### 3. 保存组件被拦

- 字段 ID 重复或为空；
- HTML/CSS/JS 有语法错误，按提示行号修；
- 出现 `document.write` 或 `innerHTML` 拼接；
- 字段改动影响页面，需要确认影响清单。

### 4. 模板套用后页面被覆盖了

覆盖前平台会先备份。去 `backups/` 找对应时间戳，按 `manifest.json` 恢复。界面没有一键回滚模板套用。

### 5. 模板导入被拒

- 文件不是合法 JSON；
- 模板缺少 `format: "lowcode-template"`；
- 单文件超过 512 KB；
- 拖拽区不在 Builder 的「组件库 / 模板库」标签里。

### 6. 主题保存后没生效

- 是否点的是「保存到站点」而不是只改色板；
- 顶部是否还有「未保存改动」；
- Builder 点「重新加载」；
- 站点是否选错；
- 「允许访客切换」是否勾选了这套主题（未勾选不会进导出 CSS）。

### 7. 主题保存被拦

对比度校验没通过。按「实时校验」提示把正文/背景调深或调浅，问题清零再保存。

## 六、数据源与接口

### 1. 集合不存在

- 数据源页面站点选错；
- 集合 ID 拼错；
- 集合被删。

### 2. 导入失败

- 单文件 > 5 MB 或 > 2 万行：拆分后再导；
- 没有映射任何列：至少映射一列；
- 唯一冲突：换冲突策略，或先清理重复数据；
- 类型不符：检查列映射的目标字段类型。

### 3. 接口测试失败

看失败分类：

| 分类 | 先查什么 |
| --- | --- |
| 网络 | 地址是否可达、DNS、代理、防火墙 |
| 超时 | 调大超时，或对方服务是否慢 |
| 认证 | 密钥是否勾选「密钥」并填写、请求头是否正确 |
| HTTP 状态 | 对方返回 4xx/5xx，看状态码与响应体 |
| 格式 | 响应不是 JSON，或数组路径不对 |
| 响应过大 | 调大上限，或让对方分页 |

### 4. 测试成功但页面没数据

数据源页面的「测试连接」只验证接口本身。页面还需要：

- 后端流程读取并返回；
- 或自定义组件实例配置「实例数据来源」；
- 或组件数据源名称已在运行时注册。

三者都没配，页面不会自动请求。

### 5. 滑块显示「数据源尚未注册」

填的「数据源名称」不在渲染运行时注册表里。当前界面没有注册入口，需要运行时代码注册；不注册就退回静态 min/max，这是预期降级。

### 6. 滑块一直显示「正在加载数据源…」

- 数据源脚本没返回 Promise / 一直 pending；
- 请求没超时；
- 切换名称后旧请求未取消。

检查运行时代码和浏览器 Network 面板。

### 7. 滑块失败或空结果

- 失败：显示「数据源请求失败，请重试」，状态 `error`；
- 空：显示「数据源没有可用取值」，状态 `empty`；
- 检查返回结构是否符合「区间取值」或「按档位取值」。

## 七、后端积木

### 1. 生成按钮没反应

先看校验结果。有阻断项时不会写文件。常见：

- 没有启用入口；
- 路径不以 `/` 开头；
- 集合不存在；
- JSON 字段非法；
- 当前目标语言不支持某节点。

### 2. 换了 Rust / Go 后节点报错

外部 HTTP、后端组件、用户代码节点在当前版本对 Rust / Go **暂未开放**。换回 Node，或替换节点。

### 3. 预览启动失败

- Rust 目标缺 `cargo`，Go 目标缺 `go`；
- 端口被占用；
- 数据库连不上；
- 构建失败，看启动日志。

### 4. 请求测试 404

- 入口路径与测试路径不一致；
- 流程改完没重新生成；
- 预览没启动；
- 绑定的方法与入口方法不一致。

### 5. 用户代码被覆盖

不会。用户区在 `src/custom/`，生成只写生成区。只有「恢复原样」会主动删除用户区文件。

### 6. 想更新/删除集合行

当前没有对应积木。用用户代码节点（Node 目标），或在外部接口里处理。

## 八、导出与部署

### 1. 导出成功但双击打不开

Web 静态产物必须通过 http(s) 访问。用 nginx 或本地静态服务器；想双击就用 Tauri 桌面。

### 2. 导出被拦

- 站点域名格式不对；
- 应用标识符含非法字符（Android 不能含连字符）；
- 版本号带 `v` 前缀；
- 自动更新开了但没填 https 地址/公钥；
- 私钥进了导出包；
- 选定页面导致死链（只是提示，不一定阻断）。

### 3. 导出失败 / 卡在压缩

先看失败项与阶段文案。大图片、开启 HTML 压缩、页面很多都会慢。关掉「压缩 HTML」通常更快。

### 4. 部署后接口 404

- 导出时是否选了后端模板；
- nginx 是否把 `/api/` 反代到后端；
- 后端是否正常监听 8080；
- 路径前缀是否和 nginx location 一致。

### 5. 部署后资源 404

- 子目录部署是否加了 `alias`；
- 路径前缀是否与 nginx 一致；
- 是否手写了绝对路径。

### 6. 跨域被拦

- 同源不需要 CORS；
- 跨域配 `LC_CORS_ORIGINS`，写完整 origin；
- `credentials: true` 不能配 `*`；
- OPTIONS 预检是否被 nginx 转发。

### 7. 安卓安装提示 ABI 不匹配

装错包。真机装 universal 或 arm64；只有 x86_64 的包只适合模拟器。详见第 09 章。

### 8. HTTPS 证书报警

- 自签证书本来就不受信任，测试用 `-k`；
- 正式环境换可信证书；
- SAN 必须包含实际访问域名；
- 证书有效期不足 30 天会被导入脚本拒绝。

## 九、数据安全：不要做的事

排错时最容易把小问题变成大问题。以下操作不要做：

- 不要用记事本/VS Code 直接改 `data/sites/` 下的 JSON；
- 不要删 `.lowcode/` 目录来“解锁”；
- 不要在服务运行时复制/移动站点目录；
- 不要把密钥、证书私钥贴到聊天或日志里；
- 不要为了绕过校验改 `platform.config.json` 里的未知字段；
- 不要把 `backups/` 和 `versions/` 当长期归档（有保留上限）。

要改内容，走界面；要恢复，走版本/备份；要迁移，走第 11 章。

## 十、提 issue 时带什么

按这个模板收集，能省很多来回：

```text
1. 平台版本：package.json 里的 version
2. 操作系统与 Node 版本：node -v
3. 操作路径：在哪个页面、点了什么、填了什么
4. 期望结果 / 实际结果
5. 错误文案（原文，不要转述）
6. logs/boot-error.json（如果存在）
7. diagnostics.html 的截图或状态文本
8. npm run doctor 的输出
9. 浏览器控制台第一条红色错误
10. 是否可稳定复现
```

不要附密钥、证书私钥、完整站点数据。

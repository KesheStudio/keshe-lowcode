# 02 新建项目：类型、起步模板与创建后的变化

> 本篇目标：弄清「纯静态」和「带后端」到底差在哪里，知道四套起步模板各会生成什么，并能根据用途选对类型和模板。
>
> 本篇不涉及导出细节。导出放在第 09 章，后端积木放在第 07 章。

---

## 一、先看结论：两种项目类型的真实差异

新建项目时只有两个类型选项：`纯静态` 和 `带后端`。它们不是两套完全不同的编辑器，而是同一个 Builder 加上不同的后端能力。

| 对比项 | 纯静态 | 带后端 |
| --- | --- | --- |
| 页面、组件、主题、模板 | 一样 | 一样 |
| Builder 顶栏「后端代码」入口 | 不显示 | 显示，可编辑后端用户区代码 |
| 项目导出时的默认形态 | 静态站点 | 静态站点 + 服务端工程模板 |
| 后端语言 | 无 | 创建时选 Rust / Node / Go，默认 Rust |
| 数据源页面 | 可打开 | 可打开 |
| 中间件、配置中心页面 | 可打开 | 可打开 |
| 平台自带的集合/文件存储 | 没有平台服务端可调用 | 导出后可随服务端工程使用 |

### 一个容易被文案误导的地方

新建项目弹窗上写着纯静态「编辑器里不出现后端、中间件、数据库入口」。当前版本的实际行为是：

- **只隐藏** Builder 顶栏的「后端代码」按钮；
- 「数据」「中间件」「配置中心」入口仍然显示，页面也能打开。

所以不要理解为「纯静态项目点进去就报错」。正确的理解是：

- 数据源可以配置，外部 HTTP 接口这类前端能直接调用的数据源仍可能用得上；
- 依赖平台后端集合、文件存储、鉴权的绑定，在纯静态产物里没有服务端可调用；
- 中间件和配置中心的内容，只有在导出时附带后端模板的情况下才会写进服务端配置。

### 带后端的三种语言怎么选

| 语言 | 新建弹窗里的文案 | 适合谁 |
| --- | --- | --- |
| Rust | `Rust（默认，axum + sqlx）` | 不想额外选，跟默认走；导出的是 Rust 服务工程 |
| Node | `Node` | 本机已装 Node，想快速改服务端代码 |
| Go | `Go` | 团队服务端用 Go，或部署环境已有 Go 工具链 |

这个选择影响的是**导出的服务端工程模板**，不影响页面怎么搭。页面、组件、主题在三种语言下完全一样。

> 注意：后端积木的「目标语言」是另一套选择，在 `backend-flow.html` 里单独选。两者不要混为一谈，详见第 07 章。

## 二、四套起步模板各是什么

「起步模板」下拉框里除了默认的「空白站点」，还有四套内置模板。它们都是**纯数据**：套用后生成普通页面和普通区块，不存在一段你改不动的模板代码。

| 模板 | 页数 | 生成哪些页面 | 结构特点 | 适合 |
| --- | --- | --- | --- | --- |
| 文档站 | 3 | 文档首页 `index.html`、快速开始 `quickstart.html`、配置说明 `config.html` | 顶部导航、左侧多级目录、右侧本页目录、面包屑、上一篇/下一篇、页脚 | 产品手册、开发文档、知识库 |
| 落地页作品集 | 1 | 作品集 `index.html` | 英雄区、作品卡片网格、关于、联系表单、顶部导航与页脚 | 个人主页、作品展示、产品落地页 |
| 后台仪表盘 | 2 | 概览 `index.html`、项目 `projects.html` | 侧栏、顶部栏、KPI 卡、折线图/柱状图、可排序分页表格 | 运营后台、管理系统的界面骨架 |
| 认证中心 | 1 | 登录 `index.html` | 居中卡片、登录表单、错误提示区；没有顶部导航和页脚 | 登录、注册、找回密码的界面骨架 |

补充说明：

- **文档站**会额外生成 3 条文章记录，右侧目录和上下篇依赖这份顺序；套用后可以直接改标题、正文和导航。
- **落地页作品集**的联系表单只是结构，提交逻辑没有接任何接口。要真的收留言，需要绑事件或接后端。
- **后台仪表盘**里的 KPI、图表、表格都是静态演示值，不连接真实数据库。页面自己也有一条「数据说明」提示。
- **认证中心**的错误提示区是界面示例，登录校验、账号锁定这些逻辑要接后端才有。
- 四套模板都会自动把站点主题切到一套对应配色，不需要你手动改主题。

### 空白站点和起步模板的区别

| 选择 | 创建后得到 | 适合 |
| --- | --- | --- |
| 空白站点 | 1 个空首页 `index.html` | 想从零搭，或先学编辑器基本操作 |
| 四套起步模板 | 完整页面 + 导航/页脚/侧栏 + 对应主题 | 想快速得到一个能改的成品骨架 |

空白站点不是「不能用」。Builder 的「组件库」里有「内置区块」，空白页也能直接插入标题、段落、按钮等基础区块。

## 三、按步骤新建项目

### 第 1 步：打开工作台

浏览器访问：

```text
http://127.0.0.1:9780/
```

如果端口不是 9780，用终端实际打印的地址。

### 第 2 步：点「新建项目」

在首页右上角点「新建项目」，弹出对话框。

### 第 3 步：填「项目名称」

例如：

```text
产品官网
```

规则：

- 不能为空；
- 最多 80 个字符；
- 允许中文。

名称只影响显示。真正落盘的站点目录 ID 会做转换：英文名生成可读 slug，中文名生成 `site-<8位哈希>`，重名时自动加 `-2`、`-3`。

### 第 4 步：选「项目类型」

- 只是展示页面、文档、作品集，不需要登录和数据库：选「纯静态」；
- 需要后端接口、登录鉴权、集合存储、文件上传：选「带后端」。

### 第 5 步：带后端时选「后端语言」

只有选中「带后端」后，下面才会出现「后端语言」下拉框。默认是：

```text
Rust（默认，axum + sqlx）
```

不想额外决策就保持默认。切换回「纯静态」时，这个下拉框会隐藏，已选的语言会被清空；再切回「带后端」会回到默认 Rust。

### 第 6 步：选「起步模板」

下拉框第一项是「空白站点」。四套模板的选项会显示成：

```text
文档站 · 3 页
落地页作品集 · 1 页
后台仪表盘 · 2 页
认证中心 · 1 页
```

第一次练习建议选「空白站点」；想直接得到成品骨架，就按上一节的用途表选。

### 第 7 步：点「创建并进入编辑器」

按钮在对话框右下角。点击后：

1. 按钮变成「创建中…」；
2. 服务端创建站点目录；
3. 如果选了起步模板，继续套用模板；
4. 浏览器跳转到 `builder.html?site=<站点ID>`。

创建过程中不要重复点击，也不要在模板套用完成前关闭窗口。

### 创建失败时

错误会显示在对话框内的红色文字里，按钮恢复可点。最常见的原因是：

- 项目名称为空；
- 数据目录不可写；
- 磁盘空间不足。

如果项目已经创建成功、但起步模板套用失败，会弹出浏览器提示：

> 起步模板套用失败：……。已创建空白项目，可在模板库重试。

这时项目本身还在，只是页面是空的。回到工作台能打开它，也可以去「模板库」重新套用。

## 四、创建后，项目里发生了什么

### 套用起步模板时

服务端会做这些事：

1. 在 `pages/` 下写入模板页面；
2. 文档站还会在 `articles/` 下写入文章记录；
3. 把模板的导航、页脚、侧栏、面包屑引用写进 `project.json`；
4. 把站点主题切换成模板指定的主题；
5. 删除新建时自动生成的空白默认首页，避免出现两个「首页」。

模板**不会**改动：

- 数据源配置；
- 重定向/中间件配置；
- 导出配置。

所以套用模板后，后端地址、域名、路径前缀这些仍然要自己按第 09 章配。

### 页面冲突时

如果目标站点已经有同名页面或同路径页面，模板不会覆盖旧页面，而是自动改名：

- 页面 ID 冲突：加 `-2`、`-3`；
- 页面路径冲突：后缀加在 `.html` 之前，得到 `index-2.html`，不会出现 `index.html-2`。

### 磁盘上会生成什么

新建成功后，平台根目录下会多出：

```text
data/sites/<站点ID>/
  site.json             站点元信息：名称、创建时间、状态
  project.json          站点配置：主题、导航、页脚、导出配置
  pages/home.json       默认首页
  themes/ink-green.json 默认主题
  data/sources.json     数据源配置
  components/           自定义组件
  templates/            页面模板
  data/collections/     集合数据
  assets/               图片、字体、图标
  backups/              站点备份
  versions/             页面历史版本
  builds/               导出构建的中间产物
```

不同版本可能还会多出一些预留的空目录，这是正常的。平台级的导出产物不放在站点目录里，而在平台根目录的 `exports/` 下。

> 安全提醒：服务运行期间，不要用外部编辑器直接改这些 JSON。Builder 有自己的保存、草稿和版本机制，外部改动可能被下一次保存覆盖。要改内容，走界面；要做备份或迁移，走第 11 章的流程。

## 五、怎么选：一张决策表

| 你的目标 | 建议 |
| --- | --- |
| 产品文档、使用手册 | 纯静态 + 文档站 |
| 个人作品集、活动落地页 | 纯静态 + 落地页作品集 |
| 只做界面演示的管理后台 | 纯静态 + 后台仪表盘 |
| 管理后台要连真实数据、要登录 | 带后端 + 后台仪表盘，之后接数据源和后端积木 |
| 登录页只是展示 | 纯静态 + 认证中心 |
| 登录要真的校验账号、发令牌 | 带后端 + 认证中心，之后接鉴权中间件与后端流程 |
| 需要上传文件、写数据库 | 带后端 |
| 只要一个空页面练手 | 纯静态 + 空白站点 |

一句话判断：**页面能在浏览器里独立完成的事，纯静态就够；需要保存数据、校验身份、读写文件，就选带后端。**

## 六、常见问题

### 1. 创建后还能改项目类型吗？

当前工作台没有「切换项目类型」的按钮。创建时的类型主要决定 Builder 是否显示「后端代码」入口。

导出向导里可以单独选「无后端 / Rust / Node / Go」，但那是**本次导出的选项**，不会把纯静态项目变成带后端项目，也不会让 Builder 冒出「后端代码」按钮。

如果确实需要从纯静态转成带后端，稳妥做法是：新建一个带后端项目，把页面、组件、主题迁过去，再按第 09 章重新配置导出。不要直接手改 `project.json` 里的字段来「试」。

### 2. 起步模板套用后，原来的页面会没吗？

不会覆盖已有页面。冲突时自动改名。只有一种例外：新建站点时自动生成的**空白默认首页**，会被模板首页替换，避免重复首页。

### 3. 为什么我的站点目录名不是项目名？

英文项目名会生成可读 slug；中文名会生成 `site-<哈希>`。目录名只用于磁盘存储，不影响界面显示。

### 4. 选了带后端，但暂时不写后端代码，可以直接导出静态站吗？

可以。导出向导里把后端选项选成「无后端」，产物就是静态站点。后端语言只影响你选择附带服务端模板时的工程语言。

### 5. 空白项目怎么开始？

进 Builder → 左侧「组件库」标签 → 「内置区块」→ 点「插入」。标题、段落、按钮、图片、卡片组、提示块、分隔线、代码块、文章列表都可以直接用。

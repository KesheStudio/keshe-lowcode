# 11 备份、版本与迁移

> 本篇目标：知道平台自动留了哪些“后悔药”，会看版本与备份目录，会手工做整站备份，能把站点从一台机器搬到另一台。
>
> 先说结论：**版本历史与自动备份能防“改错了”，但不能当整站备份用。** 真正要保命，必须停机复制整个站点目录。

---

## 一、三层保护，各管什么

| 层 | 触发方式 | 保存内容 | 能恢复什么 | 当前界面 |
| --- | --- | --- | --- | --- |
| 版本历史 | 保存页面/文件时自动记录 | 本次变更涉及的文件全量 | 单个版本涉及的变更文件 | 无入口，只有 API |
| 自动备份 | 删除、覆盖、恢复前自动创建 | 受影响文件的原件 | 被覆盖/删除的那几个文件 | 无入口，只有磁盘 |
| 整站备份 | 你手工复制目录 | 整个 `data/sites/<站点ID>/` | 整站 | 无按钮，手工操作 |

三者的保留策略也不同：

- 版本：最近 **100 条**，且不超过 **30 天**；
- 备份：最近 **10 份**，且不超过 **30 天**，累计不超过 **2 GB**；
- 整站备份：由你自己保管，平台不自动清理。

版本和备份都遵守“最新一份永不删除”，避免清理把最后一条也删掉。

---

## 二、版本历史

### 什么时候产生版本

平台在写入页面、组件、模板、主题、数据源等站点文件时记录版本。每个版本保存的是**本次变更文件的全量内容**，不是整站快照。

磁盘位置：

```text
data/sites/<站点ID>/versions/
  index.json        版本索引：rev、parent、时间、文件、字节数
  <rev>.json        单版本条目，含变更文件内容
```

索引里每条大致是：

```json
{
  "rev": 42,
  "parent": 41,
  "at": "2026-11-08T...",
  "note": "...",
  "files": ["pages/index.json", "project.json"]
}
```

### 当前没有界面入口

Builder 顶栏**没有**「版本历史」按钮，工作台也没有。版本数据存在，API 也可用，但界面暂未开放。

也就是说，普通用户不能点两下就回滚；需要按下面的接口方式操作，或直接找 `versions/` 文件。

### 查看版本（API）

```bash
curl "http://127.0.0.1:9780/api/sites/<站点ID>/versions"
```

返回：

```json
{ "ok": true, "data": { "entries": [ ... ] } }
```

看单个版本：

```bash
curl "http://127.0.0.1:9780/api/sites/<站点ID>/versions/42"
```

### 恢复一个版本（API）

```bash
curl -X POST "http://127.0.0.1:9780/api/sites/<站点ID>/versions/42/restore" \
  -H "Content-Type: application/json" \
  -d '{"expectedRev": 50}'
```

行为：

1. 先给**当前**受影响的文件创建一份备份；
2. 在一个事务里写回该版本记录的文件；
3. 版本里标记为删除的文件会被删除；
4. 返回新的 `rev`、恢复数量、跳过数量、备份目录。

注意：

- `expectedRev` 是乐观锁。当前 rev 不等于它时返回 409，防止你恢复时别人刚好又改了；
- **不做整站回滚**，只恢复该版本涉及的变更文件；
- 恢复本身也会产生新版本和备份，所以“回滚的回滚”也有路可走；
- 版本里没有变更文件时返回 `restored: 0` 和说明。

### 适合用版本的场景

- 刚改坏一个页面，想回到上一次保存；
- 误删了一个组件/模板文件，想找回文件内容；
- 对比某次改动前后写了什么。

### 不适合用版本的场景

- 整站迁移；
- 数据库集合数据回滚（集合行不在页面版本里）；
- 想把站点恢复到一周前的完整状态。

这些要用整站备份。

## 三、自动备份

### 什么时候创建

平台在**破坏性操作前**自动创建备份，例如：

- 删除页面/文件/组件/模板；
- 模板覆盖现有页面；
- 版本恢复前；
- 部分数据源与站点配置变更。

备份是**按受影响文件**创建的，不是整站快照。

磁盘位置：

```text
data/sites/<站点ID>/backups/
  <时间戳>-<原因>/
    manifest.json
    files/<原相对路径>
```

`manifest.json` 记录：

```json
{
  "schemaVersion": 1,
  "siteId": "...",
  "createdAt": "...",
  "reason": "delete-page",
  "files": [{ "path": "pages/index.json", "hash": "...", "bytes": 123 }],
  "bytes": 123
}
```

### 怎么手工恢复

界面没有“备份列表”和“一键恢复”。需要手工操作：

1. 先停服务（避免边写边覆盖）；
2. 打开对应备份目录的 `manifest.json`；
3. 把 `files/` 下的文件按原路径复制回站点目录；
4. 重新启动服务，在 Builder 里检查页面。

例如 `files/pages/index.json` 复制回 `data/sites/<站点ID>/pages/index.json`。

### 保留与清理

- 最多 10 份；
- 最多 30 天；
- 累计最多 2 GB；
- 从最旧开始删；
- 最新一份永不删除。

所以不要把自动备份当长期归档。需要长期保留，就做整站备份。

## 四、做一份整站备份（推荐）

### 第 1 步：停止服务

在运行服务的终端按 `Ctrl+C`，确认进程退出。

不要边跑边复制：站点有跨进程锁和原子写入，运行中复制可能拿到半套数据。

### 第 2 步：复制整个站点目录

Windows PowerShell：

```powershell
$src = "C:\path\to\lowcode\data\sites\site-xxxx"
$dst = "D:\backup\site-xxxx-20261108"
New-Item -ItemType Directory -Force -Path $dst | Out-Null
Copy-Item -Path $src -Destination $dst -Recurse -Force
```

Linux / Git Bash：

```bash
cp -a data/sites/site-xxxx /backup/site-xxxx-20261108
```

### 第 3 步：打包（可选）

PowerShell：

```powershell
Compress-Archive -Path "D:\backup\site-xxxx-20261108" `
  -DestinationPath "D:\backup\site-xxxx-20261108.zip"
```

Linux：

```bash
tar -czf site-xxxx-20261108.tar.gz site-xxxx-20261108
```

### 必须包含的内容

```text
site.json
project.json
pages/
themes/
components/
templates/
data/                  集合与数据行
assets/                图片、字体、图标
.lowcode/              密钥与锁目录（含中间件密钥）
```

可选，但建议一起：

```text
backups/               自动备份
versions/              版本历史
builds/                导出构建记录
```

可以不带：

```text
.lowcode/locks/        运行期锁，目标机不需要
.lowcode/preview/      预览进程信息
```

### 第 4 步：验证备份

至少确认：

- `site.json` 存在且能打开；
- `pages/` 下有页面文件；
- `data/` 下有集合文件；
- 压缩包能正常解压。

### 多久做一次

- 重要改动前：立刻做一份；
- 日常：每天或每周一份，保留最近 4～8 份；
- 升级平台前：必须做一份。

## 五、跨机器迁移

### 前提

- 目标机器已装好同版本平台，并能正常启动；
- 目标机器没有同 ID 的站点；
- 平台版本尽量一致；跨大版本先看升级说明。

### 第 1 步：两台机器都停服务

源机停止服务后复制，目标机停止服务后粘贴。

### 第 2 步：复制站点目录

把整个 `data/sites/<站点ID>/` 复制到目标机的同名路径：

```text
目标机/lowcode/data/sites/<站点ID>/
```

目录名保持和 `site.json` 里的 `id` 一致。不要只复制 `pages/`，否则会丢主题、组件、数据源、配置。

### 第 3 步：处理锁和预览残留

删除目标机上的：

```text
<站点ID>/.lowcode/locks/
<站点ID>/.lowcode/preview/
```

这些是运行期状态，复制过去只会造成“锁被占用”的假象。

### 第 4 步：启动并验证

1. 启动平台；
2. 工作台应出现该站点；
3. 进 Builder 检查页面、主题、组件；
4. 打开数据源页面检查集合行数；
5. 打开中间件与配置中心，检查敏感字段是否需要重新填。

### 密钥与敏感值

- 中间件密钥在 `.lowcode/` 下，跟着目录走；
- 如果目标机换了环境，建议重新填一遍密钥，确认没有沿用测试值；
- 配置中心的敏感值不落站点 JSON，部署时要通过环境变量注入。

### 第 5 步：重新导出

迁移不会带走 `builds/` 里的旧产物到新环境也能用，但更稳的做法是：

1. 在目标机重新配站点域名与路径前缀；
2. 重新导出；
3. 按第 10 章重新部署。

旧产物里的基址可能还是源机的配置。

### 迁移检查表

- [ ] 站点 ID 与目录名一致；
- [ ] `site.json`、`project.json` 都在；
- [ ] 页面、主题、组件、模板齐全；
- [ ] 集合数据行数对得上；
- [ ] 中间件密钥已确认；
- [ ] 配置中心 dev/prod 值已确认；
- [ ] 锁与预览目录已清理；
- [ ] 新环境重新导出并部署。

## 六、只迁设计，不迁数据

如果只是把一套页面设计交给别人，不需要搬数据，走“模板/组件/主题”更轻：

| 内容 | 导出方式 | 带走什么 | 不带走什么 |
| --- | --- | --- | --- |
| 组件 | 组件库「导出 JSON」 | 字段、HTML/CSS/JS | 页面实例数据 |
| 页面模板 | 模板库「导出 JSON」 | 页面结构、布局、引用的组件 | 数据源、密钥、导出配置 |
| 整站模板 | 模板库「整站存为模板」 | 全部页面、组件、主题、导航页脚 | 数据源、密钥、导出配置 |
| 主题 | 主题编辑器「导出 JSON」 | 颜色令牌 | 页面内容 |

对方导入后：

1. 组件进组件库；
2. 模板进模板库，再套用到目标站点；
3. 主题在主题编辑器导入并「保存到站点」；
4. 数据源、中间件、导出配置按目标环境重新配。

这条路适合设计交付、模板复用，不适合“原样复刻含数据的生产站”。

## 七、升级平台前

升级前做三件事：

1. 停服务；
2. 整站备份（至少备份 `data/sites/` 下所有站点）；
3. 记录当前平台版本（`package.json` 的 `version`）。

升级后如果出现页面打不开、字段不识别：

- 先回滚平台版本，再恢复站点目录；
- 不要先手改 JSON“试着修”，容易把可恢复状态改成不可恢复。

## 八、常见问题

### 1. 界面里为什么找不到“备份”和“版本历史”？

当前版本确实没有这两个入口。版本与备份在磁盘和 API 层存在，界面上暂未开放。需要时按本篇的目录和接口操作。

### 2. 版本能恢复整个站点吗？

不能。只恢复该版本涉及的变更文件。整站恢复要用整站备份。

### 3. 自动备份能保留多久？

最多 10 份、30 天、2 GB，取先到者；最新一份永不删。长期归档要自己做整站备份。

### 4. 运行中直接复制站点目录可以吗？

不建议。可能复制到写入中的半套文件。先停服务。

### 5. 迁移后页面在，但数据没了？

多半只复制了 `pages/`，漏了 `data/`。重新复制完整站点目录。

### 6. 迁移后提示站点被锁定？

复制了 `.lowcode/locks/`。删掉目标机的 locks 目录再启动。

### 7. 迁移后中间件连不上？

检查目标机的环境变量、数据库地址、Redis 地址，以及 `.lowcode/` 里的密钥是否随目录带过来。

### 8. 集合数据怎么单独备份？

集合数据在站点 `data/` 下。最稳的是整站备份；也可以先在数据源页面导出/导入，但那是数据层操作，不等于站点备份。

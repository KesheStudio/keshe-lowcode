低代码平台的主题是怎么长出来的

这套东西不是把几个颜色变量换个名字就完事。它要保证同一套主题在亮色和暗色下都读得清，还得让编辑器、导出的静态站、预览页三处用的是同一份变量。

一、先定主色，其余靠派生

每个主题包只写 11 个主色：页面背景、面板背景、正文、次要文字、分隔线、强调色、代码底色，再加上成功、警告、危险、信息四个状态色。剩下的层级、浅底、描边、悬停位置都由这些颜色算出来。

这么做的好处是，不会出现「亮色模式好看、暗色模式某个按钮白字白底」这种事故。派生规则在当前链接色和面板底色上直接算对比度，不够 4.5:1 就换颜色。先看看主题包，再往下读。

为什么要拆成两套强调色

强调色在界面上有两个角色：一个是链接和图标，要放在背景上读；另一个是按钮底色，上面还要放文字。一个颜色不可能同时满足这两件事，尤其暗色模式。所以令牌里拆成 accent 和 accent-fill，各自带一个 on-accent 文字色。

凡是「一个变量既当文字色又当背景色」的设计，早晚会在某个主题里出对比度问题。宁可多一个变量，也不要在组件里写死颜色。

二、代码和表格也得跟着换

下面是示例代码块和表格。它们没有单独配色，全部引用同一套令牌：

/* 主题只通过 CSS 变量生效 */
:root[data-lc-theme="ink-ochre"] {
  --lc-color-bg: #f5efe3;
  --lc-color-accent: #8c4a26;
  --lc-color-accent-fill: #8c4a26;
}

怎么自己验证

预览页只能看外观，对比度靠脚本算。两条命令都在 lowcode/ 根目录执行：

node src/theme/check.mjs          # 主题字段 / 令牌 / 对比度 / 弱化文字 / 遮罩焦点环 / 图标集 / 断点同步
node src/theme/build.mjs          # 重新生成令牌、主题、图标 sprite、运行时、编辑器和本页

边界本页是静态文件，双击就能看，不需要起服务。它只演示外观，不代替真实编辑器的交互；键盘可达性与焦点顺序的复核记录写在 src/theme/NOTES.md。
